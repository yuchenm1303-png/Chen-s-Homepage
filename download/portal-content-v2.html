PRODUCT OVERVIEW

从商品链接，到可执行的 Makro Listing

把供应商页面采集、AI 字段理解、类目与品牌识别、草稿填写、图片上传和结果复核集中到一个 Windows 工作区。Single 与 Batch 共用同一套浏览器与安全边界。

01

单链接工作流

输入 1688 或供应商商品链接，程序采集页面文本、结构化参数、截图与商品图片，形成后续上架使用的原始证据。

02

单品与批量任务

Single 用于逐条准备与确认；Batch 让多个商品共享同一 Makro 登录会话，并在各自受控标签页中独立推进。

03

证据驱动的 AI

Local AI 先输出 READY / CONFLICT / MISSING；只有无法确认的 MISSING 字段进入补充检索，减少无依据补全。

04

浏览器持久化验收

正式执行写入草稿、上传 Product Photos，并通过 Save / reopen 验证持久化结果；Send to QC 始终留给人工操作。

LISTING WORKFLOW

四个阶段，把准备和真实写入分开

准备阶段保持零写入；只有 Fill Plan 完成后，才解锁真实浏览器执行。字段来源、阻塞原因和执行结果保留在同一条任务链中。

01采集供应商证据SOURCE CAPTURE

读取页面证据并形成商品 source bundle，不在采集阶段替商品事实做主观解释。

02确认类目与品牌CATEGORY / BRAND

连接 Makro Seller Center，完成 Vertical 与 Brand 阶段，并保持当前任务的页面所有权。

03生成字段计划LISTING PLAN

结合 Makro live schema 输出 READY、MISSING、CONFLICT 与 BLOCKED，准备阶段不写 Step 3 字段。

04填写、保存与复核FILL / VERIFY

经显式授权后执行字段填写和图片上传，Save 后重新打开验证持久化结果。

FROM INSTALL TO DAILY WORK

第一次安装之后，日常操作只保留必要动作

账号授权、Makro 登录状态和 Stable 更新都被收进正式客户端。正常使用时，用户主要面对商品链接、准备结果和明确的真实执行入口。

Windows x64Managed EdgeStable Channel
01
安装并登录 Listing Studio

使用已授权账户启动正式安装版，客户端同时验证账号权限和当前 Windows 设备。

02
完成一次 Makro 正常登录

专用 Edge 使用持久化 profile 保存正常登录状态；登录失效时程序停在登录流程等待用户完成认证。

03
粘贴单个或多个商品链接

Single 逐条处理，Batch 批量排队；不需要为每个商品重新启动一套浏览器。

04
先准备，再决定是否真实写入

先查看字段状态、缺失与阻塞，再从独立执行入口写入草稿。程序不会自动点击 Send to QC。

05
保持在 Stable 正式版本

正式客户端启动后检查 Stable 更新；安装包下载和更新继续沿用授权账户与完整性校验。

CONTROLLED AUTOMATION

自动化负责执行，关键边界仍然清楚可见

ZERO WRITE准备阶段

采集、识别和 Fill Plan 不写 Step 3，不把“分析”与“提交”混在一起。

EXPLICIT真实执行

只有独立的真实执行入口才允许字段填写、保存和图片持久化。

MANUALSend to QC

最终送审动作始终由用户本人决定，自动程序保持锁定。

SECURE DISTRIBUTION

下载入口和应用授权使用同一条安全边界

这里不只是安装包下载页。网页账户权限继续用于正式安装版的启动授权、Windows 设备验证和 Stable 更新下载，让版本分发和应用访问保持一致。

01
账户与设备双重验证

正式安装版启动时验证账号授权和当前 Windows 设备；设备数量受账户授权限制。

02
Stable 更新只认正式发布

应用只读取 stable update manifest。可选更新可以稍后安装；关键更新可以要求升级后继续使用。

03
私有安装包 + 完整性校验

网页和应用更新通过授权下载接口获取短时下载地址，并在安装前核对目标版本与文件校验值。
