WHAT IT HANDLES

一条任务里处理的不只是字段

从供应商页面到 Makro 草稿，中间的证据、类目、品牌、图片、浏览器和保存结果都属于同一个任务上下文。

01

Supplier evidence

页面文字、结构化参数、截图与商品图片统一归档，后续判断可以回到原始证据。

02

Category & brand

围绕 Makro 当前类目和品牌流程推进，任务在进入 Step 3 前先把必要前置状态准备好。

03

Fresh listing schema

字段计划基于当前 Makro 页面结构生成，不把旧字段清单当作永远不变的模板。

04

Product photos

商品图片跟随任务进入真实执行，并和字段一起做 Save / reopen 后的持久化检查。

05

Managed browser

连接本机 Microsoft Edge 与 Makro Seller Center，让浏览器会话、任务和标签页保持可追踪。

06

Persistence check

Save 不是结束。重新打开页面确认字段与图片仍然存在，才算完成这一轮真实写入。

SINGLE / BATCH

Single 逐个处理；Batch 共用 Makro 登录状态，但每个商品仍使用自己的任务状态和标签页。

DAILY WORK

实际使用时，就是这六步

准备和真实写入始终分开。你可以先把任务准备完整，再决定什么时候让浏览器真正执行。

01

添加商品链接

输入 1688 或其他供应商商品地址，创建单任务或批量任务。

02

采集与整理

读取商品证据，整理类目、品牌和需要进入字段计划的信息。

03

检查状态

先看 READY、MISSING、CONFLICT、BLOCKED，而不是直接开始填页面。

04

开始执行

明确触发后才连接 Makro 页面，填写字段并上传 Product Photos。

05

Save / reopen

保存后重新打开，检查刚才写入的字段和图片是否真的保留下来。

06

人工送审

草稿确认无误后，再由你手动点击 Send to QC。

FAQ

常见问题

下载、账号、浏览器和自动化边界放在这里集中说明。下面的项目可以直接展开查看。

01注册账号后为什么还不能直接下载？
注册只建立登录身份。正式安装包仍需要管理员为账号开通软件权限；未授权或已过期的账号不会解锁下载入口。
02Listing Studio 为什么需要 Microsoft Edge？
真实上架通过本机 Microsoft Edge 连接 Makro Seller Center。浏览器负责承载登录状态、商品页面和真实填写过程。
03MISSING 字段会不会被 AI 自动猜一个值？
不会为了把页面填满而强行生成值。没有足够依据时字段保持 MISSING，冲突信息则保持 CONFLICT，等待补充或确认。
04Batch 会不会让多个商品互相串任务？
Batch 可以共用 Makro 登录会话，但每个商品保持自己的任务状态和浏览器标签页，避免把一个商品的执行上下文混到另一个任务里。
05软件会自动点击 Send to QC 吗？
不会。 Listing Studio 可以准备字段、真实填写、上传图片并保存草稿，但最终 Send to QC 始终留给人工确认。
06客户端更新从哪里获取？
正式客户端只读取 Stable 发布通道。更新下载继续使用当前账号授权，并通过短时有效的私有下载链接获取正式安装包。
